# ADR-023: A host path outside the project is asked for once

**Status:** Proposed
**Date:** 2026-11-26

An agent leaves the status `Proposed`; only the owner writes `Accepted`.

Taken by delegation on 2026-11-26: the orchestrator of the security verification of `fix/rooted-reads-are-pinned` made the call, and this record writes it down. The same day, the orchestrator of the third security verification of `fix/project-stays-inside` revised it by delegation: the names and paths checked before the ask, nothing outside touched before it, a yes kept only after the run succeeded, and `--yes` for one run, never kept. The orchestrator of the fourth verification revised it again by delegation: one ask per run, every printed project string passed through one sanitiser, and a world of the same project counted as a racer.

## Context

`spwn up` is run in a project folder that may be a cloned repository, so its `spwn.yaml` is the repository author's, not the user's. A world's `workspaces:` and `knowledge:` named any host path, and an fs automation's watch path any host folder: `workspaces: [../..]` mounted the user's home read-write into a world driven by the project's own prompts, with nothing checked or asked. Plan already refused a `knowledge:` path that leaves the project, but `spwn up` never ran that rule. Refusing every outside path would break honest projects that mount a sibling repository on purpose.

## Decision

1. **A path that stays inside the project needs nothing.** Each workspace, the knowledge folder and each fs watch path is resolved against the project's root, by name and through the links the project holds (each read inside the project, never followed by the system), and used by that resolved path, with the name and access it was asked with, carried as values, never re-parsed.
2. **A path that leaves the project is never used silently, nor touched before the yes.** One that is absolute elsewhere, climbs by `..`, or is reached through a project link pointing outside is shown once, quoted and absolute as far as the project's links tell, with what it grants (a read-write or read-only mount into which world, or a watched folder whose files' names and times are recorded in the receipts and passed to the project's agent), and asked on a terminal. Nothing outside the project is stat'd, read or opened before the answer.
3. **The prompt cannot be written by the project.** Every world, agent and workspace name and every host path of spwn.yaml is checked before any reach is built: a control character refuses it (`spwn-yaml.control-character`), a workspace name must be a slug, and a path starting with `~` is refused (`spwn-yaml.tilde`), never expanded. A path holding a `:` once the `name=path:ro` grammar is read off it, as written or as resolved through the project's links, is refused (`spwn-yaml.colon`), since Docker splits a bind at its colons. The ask and the refusal print paths quoted.
4. **One ask per run, before anything of the project is printed.** `spwn up` resolves and checks every world it will start (names, paths, reaches) first, printing nothing unless it refuses, then asks once for the outside paths of all of them, then starts the first. A no starts no world.
5. **No project string reaches the terminal raw.** Every writer of `apps/cli/ui` (each line of the stepper, each table cell, each colour helper) passes the text it is given through `ui.Clean`, which writes every character `strconv.IsPrint` refuses as its Go escape (control characters, C1, bidi controls, zero-width and other format characters, line and paragraph separators) and every byte that is not UTF-8 as `\xNN`. An error's own line breaks are kept, each line cleaned. Outside the ui package, a print gives `%s` or `%v` only a literal, a ui call or what one returned; anything else is printed by `%q`; `terminal_text_test.go` holds it for `apps/cli` and for `packages/architect`'s terminal prints.
6. **A typed yes is the user's, kept outside the project, and only once its world started.** It is remembered in `~/.spwn/grants.yaml`, keyed by the project folder's resolved path, the path and the access, so the next run does not ask; another project folder, another path or another access is asked again, and a read-only yes does not serve a read-write ask. Each world's paths are kept once that world has started; a world that fails to start keeps none of its paths.
7. **Off a terminal, no kept yes refuses; `--yes` allows for that run only.** A terminal means stdin and stderr both are one, since the ask is written to stderr and read from stdin: `2>file` alone is off a terminal. Whatever was typed or pasted before the ask is discarded (the terminal's pending input flushed, as `tcsetattr(TCSAFLUSH)` does), so only a key pressed once the ask began answers it. Off a terminal, the command fails with `outside.not-granted`, naming each path and what it grants, before anything runs. `--yes` on `spwn up` (and on `spwn automation daemon`) answers the ask for that run, prints each path it allowed and what it grants on stderr (`allowed for this run: …`) so a CI log shows it, and keeps nothing. One flag, no alias, the root grammar's `--yes` on an action that asks.
8. **A path given on the command line is the user's.** A workspace passed with `-w` is not asked.
9. **A world of the same project is a racer, so every project path is resolved again where it is used.** A running world may mount the project read-write and rewrite its links while another world starts. Each workspace and knowledge path spwn.yaml declares is resolved again just before its world's container is made and once more after it started, and each fs watch path before the watches start and after; a path that now resolves elsewhere refuses that world (`outside.changed-while-starting`, naming the path quoted, what it resolved to then and now), its container removed, and none of its paths kept. What is bound is the resolved absolute path, never the text of spwn.yaml.

## Consequences

- An honest project with everything inside it sees no change; one that mounts a sibling folder is asked once per path.
- A CI run of a project with outside paths needs `--yes` on every run, or a grant kept by a typed yes; a README line telling to run `--yes` grants nothing beyond that run.
- The grant is per path, not per world: a second world mounting the same granted path with the same access is not asked again.
- The grant is tied to the project's FOLDER path, not its content: a different repository later cloned or moved into the same folder inherits it, and so do later edits of the same project. `~/.spwn/grants.yaml` lists every kept grant; it is revoked by editing the file and deleting its entry (no command does it).
- The path shown for an outside link is where the project's link points, not where that outside path itself resolves: the user is shown the path the project names, and the bind follows it as the system does, after the yes.
- What a world's agents write to the terminal by design is not cleaned: `spwn agent talk`'s reply, an attached session, a container's log followed. It is the agent's terminal, and it can only be written after the run's one ask, since every world starts after it.
- This closes the mounts, not the trust: every world still receives the user's credentials read-only and the gh cache read-write, so running a cloned project's agents trusts that project ([Worlds](../concepts/worlds.md)).
- A window remains open: Docker resolves a bind source by its path when the container starts, never through a held descriptor, so a link swapped after the check before Create and swapped back before the check after Start is not seen, and the container keeps what it bound. The window is about the time of Create plus Start; a world of the project, or any process writing the project folder, can race it. Closing it needs a bind by descriptor, which Docker does not offer.
