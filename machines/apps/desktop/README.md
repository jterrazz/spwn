# Spwn, the desktop window

The desktop window of Machines, named Spwn: a Tauri 2 shell around a React page set, and a client of the engine's socket. It shows what a Mac's engine answers through `station.api/v2` and decides nothing itself.

## The dependency rule

Each row is a layer of `typescript.architecture` in this folder's `studio.config.ts`, so `typescript check` run from `apps/desktop` fails an import that crosses it as `architecture/<name>`. A spec under `__tests__/` stands outside the map.

| From                             | Never imports                                                                                          | Layer                        |
| -------------------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------- |
| `src/presentation/ui/`           | anything of the app but `src/domain/tone.ts` and `src/domain/separator.ts`                             | `ui-knows-no-app`            |
| `src/infrastructure/`            | `src/presentation/`                                                                                    | `adapters-draw-nothing`      |
| `src/presentation/words/`        | `ui/`, `navigation/`, `kit/`, `features/` and `screens/` of `src/presentation/`                        | `words-draw-nothing`         |
| `src/presentation/dependencies/` | `ui/`, `navigation/`, `kit/`, `features/` and `screens/` of `src/presentation/`                        | `dependencies-draw-nothing`  |
| `src/presentation/navigation/`   | `src/presentation/screens/`: `main.tsx` hands it `PAGES`                                               | `navigation-knows-no-screen` |
| `src/presentation/features/<x>/` | another `features/<y>/`, and any `screens/`                                                            | `feature-is-independent`     |
| `src/presentation/screens/<x>/`  | another `screens/<y>/` (the machine's tabs are one screen); only `screens/registry.tsx` names them all | `screen-is-independent`      |

The rest of the hexagon is the toolchain's own map, derived from this tree and sparing `__tests__/` at every boundary: `hexagonal-domain-is-pure`, `hexagonal-use-case-reaches-ports`, `hexagonal-composition-wires-infrastructure` (only `src/composition/` imports `src/infrastructure/`), `hexagonal-composition-is-the-root` (only `src/main.tsx` imports `src/composition/`), `hexagonal-kit-knows-no-feature` (`src/presentation/kit/` is what features and screens share) and `hexagonal-feature-is-independent` (a feature never imports another feature). The rows above are what that map does not say, and `feature-is-independent` adds the one crossing it leaves open, a feature importing a screen.

`main.tsx` asks `compose` for the window's dependencies (the engine, the opener, the presence) and hands them to `EngineProvider` (`src/presentation/dependencies/dependencies.tsx`); a component reaches them through its hooks, and whether an engine answers by `useReach()`, never by a prop.

The root's `typescript check`, the one `make check` runs, judges both maps: since `@jterrazz/typescript` 12.3.0 each unit, the root and every member, is read once from its own folder, so an import crossing a layer fails the root gate as `architecture(<rule>)`. A probe of 2026-11-16, a file of `src/domain/` importing `src/presentation/kit/`, was refused from the root.

## The law

- The engine owns every judgement: each verdict, state, count and sentence shown is a field it computed.
- The window owns layout and interaction: it never derives a state from numbers, never composes a verdict, never guesses a role.
- What no call gives is left empty in a way that does not lie, by `NoVerdict` or `NotGiven`, and named as a missing field.
- Whether an engine answers on the socket is the transport's state, `reachOf` (`src/application/use-cases/reach.ts`), read by every page and the frame through `useReach()`, and shown by the sidebar's Engine line and the bar's engine mark, "No engine answers at <socket>", in the word `ownState('engine-absent')`, and by a page's `Absent` in the same sentence where the page has nothing of the engine's to draw yet. While the shell declares no engine answering this window's own socket ([below](#the-link-to-the-engine)) and the window has never drawn the engine's machines, it draws no page: Home holds the core's panel ([below](#with-no-engine-the-window-installs-the-core)). Once it has drawn them, an absence keeps every page and sheet drawn, and the foot line alone says it. An engine whose state stream says this window does not fit it is `incompatible`: running, never absent, and its verdict's panel stands in every page ([below](#the-compatibility-verdict)). The engine's own state (Running, Stopped) is `engine.read`'s alone, worded by `engineState` from `words.json`.
- An enum the engine words (`@jterrazz/station-api/words.json`: a VM's and a Mac's standing and their roll-up, an engine's state, a check, a condition, a setting's state and an action, a package's kind, level, need and restart, a Disk group, a refusal's type, a finding's severity, a section, a lifetime, a layer, a system, and the nouns a count is said in) is shown by its word, its tone and its detail through `src/presentation/words/engine-words.ts` alone, the one module that reads the file, typed by `StationWords`; a count is `countOf` or `nounOf`, never a plural written in the window. The engine's tone becomes the one the design draws in one place, `toneOf` (`src/presentation/words/shown.ts`), behind `engineShown`. Any other enum code is shown by its word from `src/presentation/words/words.ts` and its tone or colour from `src/presentation/words/tones.ts`, each typed by the generated enum; a tone is the engine's `CoreVerdictTone` (`src/domain/tone.ts`). What the wire does not carry yet (a need's input, whether a port is shared, a row's gesture) is read once, in `src/presentation/words/provisional.ts`, named for the field the engine owes.
- `src/presentation/words/shown.ts` holds no table: it pairs a code's word with its tone into the `Shown` a state component draws, and shows a code no table has as it came, in the plain tone. The window's own states (a read not answered yet, a gesture done or of unknown outcome, an engine installed and not started) are codes of `OwnState` in the same two tables, drawn through `ownState`.
- Those four files and the engine's reader are the only place a code becomes a word, a tone or a gesture, a confirmation's form included: `useGesture` reads it from `@jterrazz/station-api/confirms.json` through `confirmingOf` (`src/application/use-cases/confirms.ts`), and a page has no way to name one. Each table goes when its enum joins `words.json`.
- `src/presentation/words/__tests__/words.test.ts` fails a file of `screens/`, `features/`, `kit/`, `navigation/` or `dependencies/` that writes a tone or a word into `StatePill`, `StateDot` or `Verdict`, a tone literal into a state, a wire field (`PascalCase`) compared with a code, a `Record` keyed by a wire type's field, or a reading sentence (`Reading its lines…`) written in place of `readingWord`. It names its exceptions, each with its reason. It also fails, anywhere in `src/` but `engine-words.ts`, a `Words` or `Tones` keyed by an enum `words.json` covers, or a `Record` of one to a word or a tone, by its name or by a field of `index.d.ts` that carries its codes, both read from the generated files, so the rule grows as the engine words more; a `Record` of one to a colour, a gesture or a tab is the window's own and stays. It cannot see a lowercase wire field compared (`ports.list`, `accounts.list` and `activity.read` name theirs so), a code copied into a variable first, a `switch` over a code, or a word composed from a boolean: those stay the review's. The sweep of the pages (now `src/presentation/screens/` and `features/`) and `src/presentation/navigation/` for those four on 2026-11-13 found one, a disk's `Pending` worded inline, now `DISK_PENDING_WORD`.
- A code the generated type leaves a plain `string` or `number` has its words under one type, `WordsOfAnOpenCode`, and is shown as it came when the table has no word: a thermal level (`ActivitySample.thermal`), a port's reach (`PortsPort.Reach`).
- The one screen the window applies of its own is SAFETY, not judgement: a text shaped like a secret is drawn "Withheld" by `shownOrWithheld` (`src/presentation/ui/secret.ts`), applied where a value and an engine's error text are drawn (`Value`, `ProgressLine`, `ConfirmDialog`, the kit's `Unanswered` and `Unknown`), and `OpenButton` holds a value so shaped unopened. A pasted login code is no value the window draws: it stays in an uncontrolled input and one `accounts.answer` frame (`PasteCode`, `src/presentation/kit/paste-code.tsx`), never in state, a log or a golden. A typed password is no value either: it stays in an uncontrolled password field with no reveal and no Copy, is read from it into one `vault.add` frame and emptied as it leaves, on a refusal, a cancel and an unmount alike (`useAdd`, `src/presentation/screens/passwords/use-add.ts`), and the bridge drops the request once written. Its spec proves a path, a version and an image digest are still shown.
- A mark is IDENTITY, not judgement, so the window draws it, the menu bar app's first: `markOf` (`src/presentation/ui/app-marks.ts`) draws the menu bar's own mark for a name when it has one (15, `MENUBAR_MARKS`, reached through `ALIASES` for `gh`, `claude-desktop`, `github-release` and `kubectl`), else its [Simple Icons](https://simpleicons.org) logo (37 names, `LOGOS`), else its first two letters or digits. No call carries an icon (`CatalogApp.Bundle` names a macOS bundle the webview cannot draw), so `AppIcon` (`src/presentation/ui/app-icon.tsx`) takes the engine's own name (`App.Name`, `Step.Item`, an account's `provider`, `DiskRow.App`); a setting is drawn by its first two letters (`LETTERED_KINDS`), as the mockup's tile is, even when it bears an app's name, and a name shaped like a secret by an empty tile. Every mark is drawn alike: one colour, the text tone, on the menu bar's 20 px box (a logo set on 16 px of it), in the mockup's raised 24 px tile, so no one can tell a source from another. The menu bar's marks have one owner, its `scripts/symbols.swift`: `scripts/menubar-marks.sh` writes `src/presentation/ui/menubar-marks.ts` from it, and `menubar-marks.test.ts` fails when the two drift. The menu bar draws an account it has no mark for by the SF Symbol `key`, which a webview cannot draw: the window draws its two letters. The logos come from the package `simple-icons` pinned at 16.36.0 (CC0-1.0), their paths bundled and nothing fetched. The tables map a name to a drawing, never a code to a word or a tone, so the law spec leaves `src/presentation/ui/` unswept and lists no exception for it.

## Adding a page

1. Its route: a name in `PLAIN_PAGES` or a tab in `TABS` (`src/presentation/navigation/route.ts`), its case in `Body` (`src/presentation/screens/registry.tsx`).
2. Its folder under `src/presentation/screens/`: the page reads the engine with `useRead` or `useWatch`, and renders, for the states it does not have yet, a skeleton of its own geometry before the first answer (`Skeleton`, `SkeletonHead`, `SkeletonPanel`, `SkeletonRows`, `SkeletonTile` from `src/presentation/kit/skeleton.tsx`, drawn with the bones of `src/presentation/ui/`: `Bone`, `RowSkeleton`, `VerdictSkeleton`), then `Unanswered` and `NoVerdict` from `src/presentation/kit/readings.tsx`. A read is aimed by `targetOf` (`src/domain/machines/machines.ts`), so a read of this Mac names no target, the socket's engine being its own. It is one request per call, input and target compared by value (`src/application/use-cases/store.ts`): components asking the same share it, its input needs no `useMemo`, and every read is asked again when the engine restarts and kept fresh by the store ([below](#a-read-stays-fresh)), but This Mac's fleet and Overview, which the engine pushes ([below](#the-engines-views-are-mirrored)); a page keeps no timer of its own for it.
3. Its calls in `scripts/record.py` (`asks`), recorded again by `make generate` in the VM.
4. Its spec in `__tests__/`: its worlds loaded once before any render, `const recordingFor = await recordingsOf('two-macs', …)` (`src/infrastructure/outbound/engine-replay/recordings.ts`), then `pageOver(recordingFor(world), route)` rendered by `component.render`, its tree compared to a golden in `__expected__/`.

## A read stays fresh

A watch the engine ends (`done`) and a plain read are an answer of one moment, so the read store (`src/application/use-cases/store.ts`, its triggers in `src/application/use-cases/fresh.ts`) asks again every read a component holds, and nothing else does.

- It asks on each `notice` of `engine.events` where the engine's hello lists that call. A notice names no read, so it asks them all. No timer asks, and neither does a focus regained.
- It never asks on a notice while the window is hidden (`src/infrastructure/outbound/document-presence/document-presence.ts`), never asks a read nobody holds, and never asks a read whose request is still out: a watch still streaming is live already.
- A re-ask never draws a pending out over a settled answer: the answer stays shown, and the watch's outs are held until it ends, or, for a view the engine keeps in the mirror ([below](#the-engines-views-are-mirrored)), until the engine's next revision of that view, whichever comes first; never by a timer. A re-ask over an answer still filling is loud, its outs shown as they come (`src/application/use-cases/ask.ts`).
- An error that says the answer could not be read again keeps it: one with no engine word (the request reached no engine, or its answer was lost), a far Mac's `unreachable`, a call `interrupted`. The reading carries the error as `stale`, and the next answer clears it. The page stays drawn as it was answered; every `useRead` and `useWatch` holds its reading's `stale` in the frame's marks (`src/presentation/dependencies/stale-marks.ts`) while it is drawn, and the toolbar draws them as one dimmed dot before its action, named and titled by what the engine said, with the time of the oldest answer still shown beside it, "as of 10:42" (`StaleMark`, `src/presentation/navigation/stale-mark.tsx`, its words `asOfWord`). A watch whose connection drops is asked again by the client on its own, so it keeps its answer unmarked meanwhile. A refusal said again in the same words is the reading shown, stale or failed. Any other refusal is what the engine says of the subject, and replaces the answer.
- A read nobody holds any more is closed after a grace (1.5 s), so a page that remounts keeps its request, and its answer is kept after it: the 50 left last, each for 10 minutes (`StoreTiming`, `src/application/use-cases/store.ts`). A page drawn again shows its kept answer at once and asks it again quietly; a kept read is not asked while nobody holds it.
- An answer is merged into the one shown by `replaceEqualDeep` (`src/application/use-cases/equal.ts`): a part that did not move keeps its identity, an answer equal to the one shown is that one itself, and no component hears it, so a re-ask that changes nothing renders nothing. A reading carries `at`, when its answer was read, off the store's clock (`now` of `StoreTiming`): an equal answer keeps the reading and its `at`, while the entry keeps the instant it was heard, so a stale reading is as of the last answer heard.
- A hook asked with `{ placeholder: true }` (`useRead` and `useWatch`'s last argument, `src/presentation/dependencies/use-placeholder.ts`) shows, while a new input is read, the answer of the input it asked before, marked `placeholder`, for a switch (a span, a tab's filter) that should never blank; a refusal of the new input is shown as it is.
- A gesture's `rereads` and an engine that restarts or links again ask at once, by the same rule.
- Activity keeps no timer of its own: its readers (`useActivity`, `src/presentation/features/activity/reading.tsx`, which the tiles of Home and of a machine's Overview read through too, and Home's fleet board once per Mac through `useActivities`) stay mounted and are asked again on a notice like any read; a span switched keeps the last span drawn, dimmed as a placeholder (`Placeheld`, `src/presentation/kit/skeleton.tsx`), until the new one answers. What a reader shows is derived in the render that reads its answer (`useHeard`), so the answer is drawn in the commit it arrives in; only Home's fleet board hears each Mac's from a reader of its own, one commit later.
- A notice is told only for what the HUD tells (a server down, a VM ready), so a VM stopped from the CLI asks no read that is not a view again, and the world's `guest serve` does not answer the call.

### The engine's views are mirrored

The reads the engine keeps are not asked by their calls: the fleet (`machines.list {}`), This Mac's Overview (`overview.read {}`, and `{Elsewhere: true}`), another machine's Overview (`overview.read {}` aimed at it, the view `overview.read:<machine>`), every Mac's ports and one machine's, a machine's sign-ins and a Mac's Awake are views the engine keeps ([ADR-070](../../docs/decisions/070-the-engine-keeps-one-read-model.md)), and the window reads them from one held `engine.state` stream (`StateMirror`, `src/application/use-cases/mirror.ts`; `viewOf` names which reads are views). Every other read is still the store's.

- A machine's view that the stream's first frame does not hold is one the engine keeps for no machine of that name (a server, a workspace): it is refused to its call, `not-kept`, and the store asks it, until a frame brings the view.
- The stream is opened while a view or the link is held and the link is open, and closed after the same grace once nobody holds either. Its readings outlive it, so a page once drawn never blanks. Its `opened` is the engine's verdict ([below](#the-compatibility-verdict)).
- A revision draws once: a slice is merged by `replaceEqualDeep`, a slice sent without its value keeps the one held, and one not read yet draws nothing new. An equal revision renders nothing.
- A stream silent for 45 s, three of the engine's ticks, is asked again from the revision held (`since`); one whose connection is cut is asked again a second later, its views kept meanwhile. A refusal in the engine's words is drawn as the read's failure.
- A gesture's `rereads` do not ask a view again: the engine's readers read what the gesture moved, and the stream pushes it.
- What a view says of time is drawn at the frame's instant: a VM's uptime is its boot to `useNow()` (`src/presentation/dependencies/dependencies.tsx`), never to when the fleet was read. A replay's clock is the instant its world was recorded at (`recordedAt`, `src/infrastructure/outbound/engine-replay/instant.ts`).

### A read marks its time

Every ask the store makes is measured in the webview's User Timing (`src/application/use-cases/marks.ts`): `read first <key>` from the ask to its first out, and `read done <key>` from the ask to its end, the key being the request's (`watch machines.list {} {}`). Each name keeps the last ask's measure alone, so a window open for days holds one pair per request. In a running window's web inspector, `performance.getEntriesByType('measure')` lists them, and the timeline draws them; a refused ask marks no end.

## The link to the engine

The shell says hello to the engine's socket on a thread of its own (`supervise`, `src-tauri/src/engine.rs`) and emits `engine://link` each time the link changes; the store judges it by the engine's verdict ([below](#the-compatibility-verdict)) and `reachOf` (`src/application/use-cases/reach.ts`) reads it.

- While the engine answers, no timer says the hello again: the supervisor rests until the window's held `engine.state` stream is cut from the engine's side, or an open finds no engine, or, while no `engine.state` stream is held (an engine judged incompatible), what stands at the engine's socket path changes, a socket bound anew or removed, and then says it at once (`Alarm`, `src-tauri/src/bridge.rs`; the socket's folder is watched by a kqueue, `src-tauri/src/socket_watch.rs`, from the first answer on); a stream the window closes, or the engine ends with its last frame, says nothing. A core started and a move that ran wake it too. One that fails, within 3 s to connect and 5 s to read, changes nothing the window shows: the link stays as it was and the hello is said again 5 s later (`RETRY`). The third failure in a row declares the link absent (`ABSENT_AFTER`): 10 s after the first failure is heard when each is refused at once, 20 s when each runs out its 5 s read. From there the hello is said again after 1 s, the wait doubling up to 30 s, and the first answer opens the link; `Watch` (`src-tauri/src/engine.rs`) counts the row, and its tests play it on a clock of their own.
- Each change is a line of the link log: its UTC instant to the millisecond, the link's kind, and what the hello heard, `answered` or the step it failed at (connect, write, read, answer) with that step's error; a failure that keeps the link is a line too, with its place in the row (`1 of 3 in a row, link kept`). The log is `link.log` in the app's log folder, `~/Library/Logs/com.jterrazz.spwn/` on a Mac, kept under 1 MiB with one older file beside it, `link.log.1` (`src-tauri/src/link_log.rs`). It writes no answer and no socket path: a hello's answer names the engine's executable.

## The calls the bridge forwards

`src/domain/bridged.ts` lists the calls the window sends, and it is the one list. `src-tauri/build.rs` reads it into the Rust bridge, which refuses any other name before it reaches the engine: `refused`, code `bridge.not-bridged`, drawn like any refusal. `ReadName` and `WatchName` admit only its names, so a page that reads or makes a call off the list fails the compile, and `bridged.test.ts` fails a name of the list no source sends. A call joins the list in the commit that first sends it.

A request's `in`, a sign-in's pasted code among them, lives in the one frame the bridge writes to the engine: `Exchanges::open` drops the request once written, the reader it starts holds the id alone, and a refusal names the rule broken, never the input, so nothing the window hears back carries it.

A watch the window lets go of while the link still answers (closed, asked again, gone silent) is cancelled: `Watching` in `src/infrastructure/outbound/engine-link/watch.ts` sends `{"v":2,"cancel":true,"id":<id>}` on its exchange before closing it, so the engine stops what it streams; one the engine ended, or whose link is gone, sends nothing. The bridge's `engine_cancel` writes that frame only on an exchange this window opened with that id, and refuses any other as `bridge.not-opened`, a frame of any other shape as `call.bad-frame`.

## What the window opens outside itself

Four buttons hand something to the Mac rather than to the engine: a VM header's Open in Terminal, a shared port's Open, a need's Open of a System Settings pane and a need's line filled for Terminal. They go through four Tauri commands of the shell, `open_url`, `open_in_terminal`, `open_settings` and `open_fix_in_terminal` (`src-tauri/src/opener.rs`). The only other programs the window starts are the core's installer and its engine start, while no engine answers ([below](#with-no-engine-the-window-installs-the-core)) and on the Engine page's Update ([below](#the-engine-page-offers-the-update)).

- The value is the engine's own: an `Openable` (`src/presentation/kit/openable.ts`) is made only from an answer, `machines.ssh`'s `Command`, a shared port's address, a release's `Notes`, a need's `Pane` or its `Command` when it says `InTerminal`, and its constructor is private, so no text a page holds reaches either command. The window appends nothing to it.
- A share's address opens from the window's Mac only when the engine's answer means it to: `ports.list` gives a share a `public` and a `local` address and nothing else, so its Open opens the public one, and the local one only on the row the engine flags `this_mac` (`shareOpensFromHere`, `src/presentation/words/provisional.ts`). A share of another Mac with a local address alone keeps its Open held, its reason as its title (`LOCAL_ELSEWHERE`): `127.0.0.1` there is not this Mac's.
- `OpenButton` (`src/presentation/kit/opens.tsx`) draws it: held with its reason as its title when no answer gives the value, the value as its title when one does, held too when the value is shaped like a secret (`looksSecret`, the guard Copy applies). Opening marks nothing done: the reads show what changed once the engine says so. Those three states are its stories in the gallery ([the design rules](#the-design-rules)).
- The Rust side checks again before the Mac sees anything. `open_url` takes one `http` or `https` URL with a host, at most 2048 bytes, with no space or control character, and opens it with `open` (`xdg-open` on Linux), the URL one argument and no shell between. `open_in_terminal` takes one line, at most 1024 bytes, with no control character (a line break, a NUL), writes it under a fixed header into a `.command` script of its own (mode 0700, in a 0700 folder of the temp folder), and opens that script with `open -a Terminal`. The script removes itself first, then runs the line; a script a terminal never ran is removed when the window starts. `open_settings` takes one pane and opens it with `open`, no shell: the URL must be, byte for byte, one of `PANES` in `opener.rs`, which a test of the architecture holds equal to the engine's `catalog.Panes`, so no URL the engine did not name reaches `open`; the engine sends a pane only for a Mac's own findings, and the window draws the button only on a Mac the engine flags `ThisMac`. `open_fix_in_terminal` takes a line under the rules of `open_in_terminal`, but its script prints the line, says nothing runs until Return, and waits at `read -r` before it runs the line, so a Terminal closed there runs nothing and Spwn never runs it or types `sudo` for the owner. A refusal is `opener.not-a-settings-pane`, `opener.not-a-web-address`, `opener.not-one-line` or `opener.not-opened`, drawn like the engine's but typed apart, as the window's own `WindowFailCode` (`src/domain/engine-error.ts`), never a code of the engine's wire.
- A `.command` file and not `osascript`, which the menu bar uses (`apps/menubar/sources/station-kit/engine/Terminal.swift`): Terminal runs it with no Automation consent, and the line is never quoted into AppleScript.
- The four commands, like the core's four, need no capability: an app's own commands are allowed to a local page while the app declares no app manifest, as `engine_open` is, and refused to any remote origin (`tauri` 2.12.5, `src/webview/mod.rs`). `capabilities/default.json` and the CSP are unchanged, and no `shell` or `opener` plugin is linked.
- A debug build alone reads `STATION_WINDOW_OPENED`: set to a file, each command appends what it would open there (`url<TAB><url>`, `terminal<TAB><script><TAB><command>`, `fix-line<TAB><script><TAB><command>`, `settings<TAB><url>`) and opens nothing, so a bench session proves the plumbing with no browser or terminal; a release build compiles that path out.

## With no engine, the window installs the core

A Mac where no engine answers the window's socket shows the window as ever, with a quiet sidebar and one centred panel on Home that takes it from no core to a running engine; the decision and what it never does are [ADR 058](../../docs/decisions/058-the-window-installs-and-starts-the-core-itself.md).

- The panel is `CorePage` (`src/presentation/screens/core/core.tsx`), handed to the frame as `Pages.Core` and drawn by `NoEngine` (`src/presentation/navigation/no-engine.tsx`) as the content of the window's one frame while `useHeld` says `core`: `useReach()` says `unanswered` and `machines.list` was never read. The sidebar's items are disabled but Home, its Machines say "None yet" (or "Start the engine to see them" once the core is on the disk), its foot says where the core stands (`CORE_FOOT_WORDS`, `src/presentation/words/words.ts`), and no shortcut acts. Once the engine answers, the same frame draws the pages in the panel's place: the sidebar, the toolbar and the main stay the nodes they were.
- Its five panels follow `CoreFlow` (`src/application/use-cases/core-flow.ts`), over the port `CorePort` (`src/application/ports/core.port.ts`): the offer, "Spwn is not installed on this Mac.", with what the install puts where, three assurances, the command with Copy, Install and "I'll install it from the terminal"; the install, an indeterminate progress over the installer's own lines and Cancel; the wait for a terminal, which looks for `station` every three seconds and moves on by itself; the start, "Spwn is installed. Start the engine next.", also what a core installed from a terminal with its engine stopped shows; and a failure, its pill `failed` and the run's last error line as sent for its title, with Retry, and the command when the install failed.
- The shell's side is four commands of `src-tauri/src/local_core.rs`: `core_present` (an executable `station`, looked for by `station_of`, `src-tauri/src/station.rs`), `core_install` (the installer's line), `core_start` (`station engine start`, then the bridge dials at once) and `core_cancel`. Each run's lines reach the page on a channel, through `tauriCore` (`src/infrastructure/outbound/core-tauri/tauri-core.ts`).
- A bundled release moves a Mac from B to A by itself (ADR-073): the first engine to answer after the launch is judged once by `move_plan`, and a hello whose `executable` is in no Spwn.app has the bundle's own engine run `engine start`, which boots out the bare jobs and registers the app's. No line of it is shown; its end is a line of the link log, and a move that ran wakes the bridge.
- `station` is looked for in five places, in order, never on `PATH`: the engine a window inside Spwn.app carries, `Contents/MacOS/Spwn Engine` (`bundled_of`), before any other, so the Mac stays in mode A (ADR-073); the `executable` of the engine's hello, which the page hands to `core_start`; the engine's record, `station/engine.json` under the state root; the installer's record, `station/installed.json` there too, so a core installed and never started is found; the install folder. A record is read only at `v: 1`, and a missing, unreadable or other record is passed over in silence. The install line, the folder, the binary and both records' places are `@jterrazz/station-api/install.json`'s, read into the crate by `build.rs` and imported by `src/domain/core.ts`.
- A debug build runs neither unless `STATION_WINDOW_CORE` names a folder: `core_install` then runs `<folder>/install.sh` by `/bin/sh`, and `core_present` and `core_start` read `<folder>/station` and nothing else; without it each refuses as `core.not-run`, so no test or bench reaches `spwn.sh` or a real core. A release build compiles that path out.
- A proof build plays the panels without a shell: `?core=missing`, `holding`, `terminal`, `installed` or `failing` beside `?world=` gives the window `scriptedCore` (`src/infrastructure/outbound/core-scripted/`), whose start opens the recorded world.

## The compatibility verdict

An engine that answers in a revision of its pages the window cannot draw is said to run, with the verdict and its remedy in place of every page; the rule is [ADR-070](../../docs/decisions/070-the-engine-keeps-one-read-model.md)'s one verdict, with no range until 1.0 ([ADR-072](../../docs/decisions/072-before-1-0-every-station-runs-the-same-release.md)), and its words are [the reference's table](../../docs/reference/api.md#the-compatibility-verdict).

- The verdict is the engine's: the `fit` of the `opened` frame its `engine.state` stream starts with, the window having declared the revision it reads, `STATE_REVISION` (`src/domain/fit.ts`, which `fit.test.ts` holds equal to the engine's in this tree). An `opened` that names none is an engine older than the verdict. `StateMirror` (`src/application/use-cases/mirror.ts`) keeps the verdict of the engine its link answers with, so it holds its stream while the link is held, not only while a view is; a misfit stream is closed and not asked again until another engine answers.
- The judgement runs once, in the store: `ReadStore` (`src/application/use-cases/store.ts`) hands each link and each verdict to `judgedOf` (`src/application/use-cases/reach.ts`), so an open link whose engine said it does not fit is the link kind `incompatible`, for the Tauri window and a replay alike. Until its `opened` arrives the link counts as open, so a fitting engine's first frame waits on nothing. The store asks entries only while the link is open, so once judged an incompatible engine is asked nothing but the remedy's own steps. Another engine that fits opens the link, the store asks every entry again, and the pages are drawn in the same frame, with no relaunch.
- The two verdicts, their remedies and the panel's sentences are the window's own words, `src/presentation/words/fit.ts`, the verdicts and the older engine's remedy held word for word to the reference's table by `words/__tests__/fit.test.ts`.
- The frame holds the verdict's panel (`VerdictPage`, `src/presentation/screens/core/verdict.tsx`, handed as `Pages.Verdict`) while `useHeld` says `verdict`, whatever was drawn before; the sidebar is quiet, its Machines say what to update, and the rail's Engine line says the verdict in the warn tone, never stopped.
- An engine older than this app offers "Update station here": the install line with Copy, and Update, the Engine page's `UpdateFlow` ([above](#the-engine-page-offers-the-update)) run with the hello's `executable`. This app older than the engine offers "Update Spwn": the Window panel ([above](#the-window-updates-itself)) where the window updates itself, else the sentence naming how Spwn is updated.
- A proof build plays both: `?fit=engine-older` or `?fit=app-older` beside `?world=` opens the recorded world with an engine whose state stream opens one revision below the oldest or above the newest, and ends (`fittedOf`, `src/infrastructure/outbound/engine-replay/fitted.ts`, played by `openingOf`, `state.ts` there); with `&core=update` the update restarts it fitting. Its scenarios are [E8 and E9](SCENARIOS.md#no-engine-on-this-mac).
- A proof build plays it without a shell: `?window=current`, `out`, `refused`, `install-holding` or `install-failing` gives the window `scriptedWindowUpdate` (`src/infrastructure/outbound/window-update-scripted/`), v0.21.0 running and v0.22.0 out, its install played `?pace=<ms>` apart; without `?window=` the window updates nothing and draws neither.

## Making a gesture

A gesture is a call that changes something, and every one goes through `useGesture(call, spec)` (`src/presentation/dependencies/use-gesture.ts`), rendered by `GestureButton` and `GestureOutcome` (`src/presentation/kit/gestures.tsx`). Add password is the exception: its request may carry a typed value, which the gesture store, held by the request's value, would keep, so `useAdd` (`src/presentation/screens/passwords/use-add.ts`) calls `vault.add` itself and asks the vault's reads again.

- It asks before it sends when `confirms.json` gives the call a confirmation (`confirmingOf`, `src/application/use-cases/confirms.ts`): a yes, the name typed, or nothing, by the form the file declares. A call whose form differs by the kind of machine (a server's restart is typed, a workspace's asks nothing, a Mac's is a yes) is given that kind in the gesture's spec, from `machineKindOf`. The hook reads the form itself, so a page names none. A gesture whose subject the engine names (`subject: undefined`, `disk.free-unused`, whose subject is the names it frees joined as the engine joins them) asks nothing first: it is sent unanswered, and the engine's `confirm.needed` is the question, the name typed and filled in the consequence its own `subject`.
- It runs while the engine sends progress, and settles done on the out or failed on the error, shown by `Unanswered` with its hint and fix.
- It settles unknown, never failed, when its connection drops after it was sent or it hears nothing for its `within` (10 minutes by default): the engine may have done it, so the reads are asked again and show what it now says.
- An engine refusal of type `needs-confirmation` asks again in the level the engine names; the window never judges whether a gesture is allowed.
- Once settled, every read the spec names in `rereads` is read again, and every watch of it opens again, with `journal.read` whether the spec names it or not: the engine keeps the lines of a gesture that declares them in its Mac's journal ([The journal](../../docs/reference/journal.md#what-writes-it)), and the History shows them at once.
- A gesture of a row renders through `GestureRow`: its progress and its refusal take a line of their own under the row, never its trail, and its done sits in the trail at the left of its button, so the row keeps its height; a machine's header draws Start and Stop's done the same way.
- Its state is held by its request's value (`src/application/use-cases/gesture-store.ts`), not by the component: a row the engine's next answer leaves out for a moment (a watch read again answers pending first) finds its outcome when it comes back. Two buttons of one request share it, and the dialog is the one clicked's.
- Its dialog belongs to the request too: the button clicked hands its title and verb to the store, and `GestureConfirm` (`src/presentation/kit/gestures.tsx`) draws the one dialog asking, handed to the shell as `Pages.Confirm` and drawn after its sheets, so a row rebuilt while it asks leaves the dialog open. A spec rendering a gesture outside `Window` and `pageOver` renders `GestureConfirm` beside it.
- Its outcome, once done, is drawn where the row stands, by `GestureRow`, while the re-read still lists that row. A row the re-read removes takes its outcome to `HeldOutcomes`, the panel "Done here" above the list, so it outlives the row (a need fixed from the Needs panel too, so each page that draws the panel holds it in one); a gesture of the whole list (Free what can be rebuilt, one `disk.free {}` per page) holds each of its outcomes there too, by `HoldsWhenDone`.
- Its confirmation is `ConfirmDialog`: a gesture drawn `danger`, or one confirmed by its name typed, confirms on the filled `destroy` button, and the line under its title is the call's `consequence` in `confirms.json` with `%s` filled by the subject the question names (`consequenceOf`, `src/application/use-cases/confirms.ts`), else the `message` of the engine's refusal. A page that holds a sentence of its own for the thing it asks (a password's `RemoveSentence`, a sign-in row's `Ask`) says it through `GestureButton`'s `consequence`, so a confirmation has one source.

A gesture is recorded by naming it in `GESTURES` of `scripts/record.py`, with its world and its input, `Confirm` included (a gesture the engine asks first is named twice, unanswered and answered); `make generate` (or `record.py <world>`) then sends it to a fresh world build and writes `worlds/<world>/gestures/<call>.json` with every read whose answer it changed. Its spec renders the page over that world, clicks through the dialog, and sees the reads change; the replay plays each recorded frame `?pace=<ms>` apart in a dev or proof build, so a capture can catch the running state. A gesture recorded with reads `during` it (the create of linux-2 in two-macs) has them answered as the world answered them while it ran, from its first frame to its last (`inFlight`, `src/infrastructure/outbound/engine-replay/played.ts`); `?held=<call>` stops every gesture of that call after its first frame and never ends it, so a visit sees the running state for as long as it looks, with no clock. `?unread=<call or watch>` never answers that name, so a capture sees a page's skeleton for as long as it looks; `?stale=<call or watch>` answers it as recorded once per request, then refuses every ask after with the world's first `unreachable` refusal, so the store's next ask keeps the answer stale (`stagedOf`, `src/infrastructure/outbound/engine-replay/staged.ts`); with `&link=blip` the link is heard again and asks it, so the visit sees the stale mark, as A9's does.

- The window is flat: the bar, the sidebar and the content are plain grounds, and no space has a colour of its own.

The shortcuts are `src/presentation/navigation/keys.ts` over `src/presentation/navigation/shortcut.ts`, ⌘ or Ctrl alike but for the digits: ⌘ with a digit is a space, Ctrl with one a machine's tab; while a dialog is open (`aDialogIsOpen`, `src/presentation/ui/dialog.tsx`) none of them acts, so a draft is never lost.

Back and Forward walk the window's own history, never a parent page: one stack of the routes this window session opened and a cursor, held by `src/presentation/navigation/router.tsx` over `src/presentation/navigation/route.ts`, which every navigation goes through. A change of page, machine, tab, Machine files' file, catalog item or password is one entry; a filter, a switch, a dialog or a scroll is none, as the route does not hold them; a navigation after a Back drops what was ahead, and a machine the owner goes back to that is gone draws the page's own absent state. The bar draws both after the sidebar toggle, in every state of the window, each disabled where its side of the stack is empty.

The route (page, machine, tab, the file Machine files opens on and the catalog item a shelf opens on) is kept across a relaunch (`src/presentation/navigation/route-memory.ts`); a machine the engine's whole listing no longer holds opens Home with one line saying so (`src/presentation/navigation/lost.tsx`). A page that throws draws its own frame with what broke and Reload (`src/presentation/navigation/boundary.tsx`), and the shell stays.

## Recording, capturing, proving

All three run in the VM, from `scripts/` ([its page](scripts/README.md)): `record.py` writes the worlds, a step of the root's `make generate`, so a recording the engine of the tree no longer answers so is a tree that `make generate` leaves changed; `node scripts/capture.ts <out>` photographs every page of every world, and `check.sh` is the proof, with `check-quick.sh` for the seconds between two edits. What the window must let its user do is [its scenarios](SCENARIOS.md), each a test of `specs/website/` that visits this proof build in Chromium ([Test](../../docs/guides/test.md#the-windows-scenarios)); a journey across pages is proved there, and one page's states stay its spec in `__tests__/`. Between two edits, one test file runs alone in the VM, and one spec of it by its name; a scenario file of `specs/website/` runs alone against the proof build:

```bash
cd apps/desktop && npx vitest --run src/presentation/screens/machine/sign-ins/__tests__/sign-ins.test.tsx -t "far Mac"   # -u rewrites its goldens
npm run build:proof && cd ../.. && npm --workspace specs exec -- vitest --run --project website website/home/home.spec.ts
```

From the Mac, `scripts/look.sh <lot> <test path>` runs the first in the VM and copies back the goldens it changed. Neither is the proof: `check.sh` runs what the gate runs for the window, `typescript check` included, and the Rust bridge's checks besides.

A page opens directly in a dev or proof build by its start route, `?world=<world>&page=<page>` (Machine files on one file by `&file=<name>`, a catalog item on its shelf by `&item=<name>`) or `?world=<world>&machine=<name>&tab=<Tab>`; `&core=<script>` opens it with no engine, on the core's panel ([above](#with-no-engine-the-window-installs-the-core)), `&fit=engine-older` or `&fit=app-older` on the verdict's ([above](#the-compatibility-verdict)), and `&link=blip` declares the link absent 1 s after it opens and hears it again 3 s later (`blippedReplay`, `src/infrastructure/outbound/engine-replay/blip.ts`).

In the world build the only door is `station guest serve --stdio`, which on a Mac is the engine socket's door: a call aimed at a far Mac, or at a VM of a far Mac, is routed there and answered by that machine, so a recording and a capture of a far machine's page show what that machine says. While This Mac's engine is stopped there is no socket to route it, and the call is refused: "the engine is not running".

## The design rules

- No inline style. A size computed from data is the one accepted form: a CSS custom property set on the element, typed `Measured` (`src/presentation/ui/measure.ts`), which the module's CSS draws (`width: var(--fill)`). A colour, a spacing or a tone is a class, never a value written inline.
- A control that acts is drawn pressed on one token, `raise-2`: a button, an icon button, a switch's option, a nav item, a choice card and a row that opens. A button also sinks by `--motion-press`, the hierarchy's press scale, and a filled one (primary, destroy) keeps its fill, as `raise-2` would erase it.
- A button takes one of five looks, named once in `BUTTON_VARIANTS` (`src/presentation/ui/button.tsx`): `primary` leads a screen, `plain` is any other gesture, `link` reads as a sentence, `danger` opens a destruction, and `destroy`, the filled danger, only confirms one. `destroy` is drawn by `ConfirmDialog` alone, and the button spec fails a page that names it.
- A component's states are its stories: a plain array of `{ name, props }` (`Story`, `src/presentation/ui/story.ts`) in `<component>.stories.ts(x)` beside it, covering each variant and the data states it can meet (empty, long text, missing, withheld, disabled). The gallery renders one entry per component, grouped by layer, from `src/presentation/screens/gallery/entries.ts`, and its spec fails a component `src/presentation/ui/index.ts` exports without an entry. A kit component a page draws in states of its own has its stories beside it too: `OpenButton`'s, drawn on an engine of its own whose opener is `NO_OPENER` (`OpenButtonSample`), so the gallery opens nothing.
- A page once drawn is never blank again: a read asked again draws nothing, no refreshing mark, no skeleton over an answer already shown, and an equal answer commits nothing; a restart, a far Mac that misses the ask, a watch whose connection ends and is reconnected (its new stream held from its first, pending out) and a page drawn again keep it, the miss said only by the bar's stale mark, proved by `src/presentation/dependencies/__tests__/dependencies.test.tsx`. A link still connecting is the sidebar's Engine line and the bar's engine mark, `Engine connecting`, its word `OWN_STATE_WORDS.connecting`, never a read under way.
- Answers heard in a row are drawn in one commit: every component the store, the mirror, the link or the stale marks tell is told once, at the next task, with every other told before it (`Batch`, `src/presentation/dependencies/batch.ts`), so the frames that answer a page opening, or a gesture's rereads, are one commit rather than one each.
- A sheet the window opens (Find, New machine, Add a Mac, Add a password) is held apart from the frame (`Opened`, `src/presentation/navigation/opened.ts`): opening or closing one draws the sheet alone, never the page, the path bar or the sidebar beneath it.
- What a page and a gesture cost React is a budget: Home's load, Home to Storage, New machine, Find, a Mac's Activity tab and an engine.state revision equal to the one drawn are each held to their most commits and component renders, counted from the fibers each commit leaves and never by a clock, by `src/presentation/screens/__tests__/registry.test.tsx`; a change that costs more fails there, and one that costs less lowers the budget.
- A page's first load keeps its layout and only grows: before the answer, it draws its own panels and verdict as bones of the answered heights, a panel's rows as one bone row (`SkeletonRows`, more only where the page knows the count before the answer), one quiet pulse (`--motion-wait`, stilled under reduced motion), its region `aria-busy` and its reading sentence said once to assistive tech; the main region of Overview, Ports and Passwords is never shorter after the answer than before it, and grows by what the answer adds (each screen's spec, "never gets shorter at its first answer").
- A hidden window stands still: `markVisibility` (`src/presentation/navigation/visibility.ts`) keeps the root's `data-visibility` at the page's visibility state, and `document.css` pauses every animation under `hidden`, as it stills them all under reduced motion, so the pulses of a running machine do not wake a window nobody sees (`src/presentation/ui/__tests__/state-dot.test.tsx`).
- The production build has a weight budget: the bytes of its JS, CSS and fonts, raw and brotli, and the count of font files, each a line in `src/composition/bundle-budget.ts`. `src/composition/__tests__/bundle-budget.test.ts` builds into a folder of its own and fails with a sentence naming the kind that grew and its line; a change that grows one raises its line in the same diff.
- The greys are the cool dark measured on the owner's reference, hue about 228° at about 8 % saturation, one step lighter for the column and the bar (`--side`) than for the content (`--canvas`); the menu bar's hue-free panel is another surface's rule ([ADR-093](../../docs/decisions/093-the-window-is-a-path-bar-over-a-cool-dark.md)). `src/presentation/ui/__tests__/contrast.test.ts` computes WCAG 2 ratios from `tokens.css` and fails a text level, a tone or the decoration level that drops under its bar.
- No page draws a command, a path into `~/.config/station/` or the old name `station` as a sentence. A need whose fix lives in macOS draws a button that opens the pane the engine sent, and one whose fix is a line the owner runs draws a button that fills it into Terminal, where it waits for Return; a finding's or an error's other command is behind a "Copy the command" button and never shown (`Fix.Command`, the need's `Command`), the interim of a command no call answers yet; a need with no command and no call draws no verb, only its `Path` as a quiet line when that path is not itself a command or a config path; an error's `hint` that carries one is withheld (`unlessCommand`, `src/presentation/ui/command.ts`), as `shownOrWithheld` withholds a secret. The window's own proof is `window.test.tsx`, which draws every page and every tab of every recorded world and fails on a line that holds one; the install panel of a Mac with no engine (E1 to E9) is the one place a command is shown, since no engine answers there to press.

## Its name

The window names itself Spwn, on the owner's word of 2026-11-18, with a capital S wherever a person reads the name (owner's word of 2026-11-19); a command, a path, a domain and an identifier stay lowercase `spwn`. The engine and its CLI read as Machines, the menu bar app as Spwn Menu ([Glossary](../../docs/concepts/glossary.md)).

- `src-tauri/tauri.conf.json` gives the product name `Spwn`, so a bundle is `Spwn.app`, the window's title `Spwn` and the identifier `com.jterrazz.spwn`; `index.html`'s title is `Spwn` too.
- The binary is the crate's name, `spwn-window` (`src-tauri/Cargo.toml`, pinned by `mainBinaryName` in `tauri.conf.json` so the product name never renames it), never `spwn`, which is the CLI's name on a PATH.
- Its icon is the Spwn mark, `src-tauri/icons/` ([its page](src-tauri/icons/README.md)); the window draws that same drawing as its sign, at the bar's left and at the head of the core's panel (`Sign`, `src/presentation/ui/sign.tsx`).
- What the window reads of the engine keeps its words: the socket (`…/station/engine.sock`), `STATION_ENGINE_SOCKET` and `@jterrazz/station-api`. The window's own `STATION_WINDOW_OPENED`, `STATION_WINDOW_CORE`, the npm member `station-desktop` and the route's storage key `station.window.route` keep theirs too: no person reads them.

## Its bundle

`make window`, from the root of `machines/`, builds `.artifacts/window/Spwn.app` for darwin-arm64 on a Mac with Rust and Node, and the release ships it signed and notarized as `Spwn_darwin_arm64.zip` ([Release](../../../docs/guides/release.md#cutting-a-release)).

- It runs `tauri build --no-sign --bundles app --target aarch64-apple-darwin` from this folder, in its own Cargo target (`.artifacts/window/cargo`), then copies the bundle out. `tauri.conf.json` turns the bundle on for the `app` target alone: no dmg, and no updater archive, which a signed release packs from the stapled bundle instead (`scripts/window-update.sh`, [ADR-065](../../docs/decisions/065-the-window-updates-itself-through-the-tauri-updater.md)).
- The production build loads the front end `npm run build` writes to `dist/`, embedded in the binary; `devUrl` is read by `tauri dev` alone.
- Its version is the release's: `git describe --tags --always --dirty`, its `v` dropped, passed to `tauri build` as the config's `version`, so it is compiled into the binary, where the updater reads it, and Tauri writes it into `CFBundleShortVersionString` and `CFBundleVersion`, which the target then checks. The `version` of `tauri.conf.json` (`0.1.0`) is what a dev build carries, and `Cargo.toml`'s is not read. `WINDOW_VERSION=<version>` sets it where no git history is, and it must be semver: `tauri build` refuses a bare hash.
- It carries the engine (ADR-073, mode A): `Contents/MacOS/Spwn Engine` is the darwin-arm64 `station` the release ships bare, the name Activity Monitor gives its processes, and `Contents/Library/LaunchAgents/com.jterrazz.spwn.engine.plist` is its one job, under the app's own label, which names it by `BundleProgram` (the engine serves the ssh key agent itself, ADR-076). `bundle.macOS.files` of `tauri.conf.json` places the two; `make generate` writes the definition from the catalog's label, static, with no home, environment or log path. The target copies in `ENGINE=<path>`, the release's build, or else builds one, and checks that the bundled engine's `--version` is `ENGINE_VERSION` and that the definition parses.
- It carries the menu bar as its login item, `Contents/Library/LoginItems/Station.app`, which `make menubar` builds before the bundle and `bundle.macOS.files` places; the target checks it is there, under its own bundle id.
- Its floor is macOS 26, the menu bar's (`bundle.macOS.minimumSystemVersion`), which also sets the binary's `minos`.
- It is signed by the repository's `scripts/sign-macos.sh`, ad hoc by the target and with the Developer ID on a release, always with the hardened runtime and no entitlements: nothing it starts needs one ([What the window opens outside itself](#what-the-window-opens-outside-itself)). The script seals it inside out, and signs every Mach-O beside the main executable with the bundle's own identifier, `com.jterrazz.spwn`, so Local Network resolves a helper to the app ([ADR-073](../../docs/decisions/073-spwn-app-carries-the-engine-on-a-mac-with-a-screen.md)).
- Tauri signs nothing, even in a job that holds the `APPLE_*` secrets, which it would otherwise read to sign the main executable and the outer bundle alone and notarize them, the login item left as `make menubar` signed it. The script's `verify` step then checks every Mach-O in the bundle, the login item's included, for the hardened runtime and the outer bundle's team, and `scripts/sign-macos-test.sh` proves it refuses the layout Tauri's own signing left.
- Its binary is built under `[profile.release]` (`src-tauri/Cargo.toml`), [Tauri's size guidance](https://v2.tauri.app/concept/size/) but for the last line: `lto = true` and `codegen-units = 1` let LLVM drop what no path reaches; `opt-level = "s"`, because the shell moves bytes between a socket and a channel, which `std` does at its own optimisation, and waits on the engine otherwise; `panic = "abort"`, so a panic in the bridge's reader or the supervisor ends the window and macOS writes a crash report, where unwinding would end that thread alone and leave its exchange unanswered for ever; and `strip = "debuginfo"`, not Tauri's `true`, so the symbol table stays and a crash report names the Rust functions it crossed (1.75 MB on disk and 0.25 MB gzipped more than `strip = true`, never paged in until a report is read). Built so on macOS, the binary is 6.6 MB (2.4 MB gzipped) against 14.9 MB (4.4 MB) with no profile.
- The Linux bench never bundles: its checks build and test the crate alone.

## The window's chrome on a Mac

On a Mac the window is drawn as a native app with a unified toolbar: its traffic lights sit in the top bar's row, over a discreet vibrancy. Everywhere else (the Linux bench's WebKitGTK, a headless capture, a page outside Tauri) it is drawn opaque, as before.

- The top bar's row is one token, `--chrome-row` (52 px, `src/presentation/ui/tokens.css`): the path bar's height, across the whole window over the sidebar and the page, a deep drag region whose every segment and button stays clickable. The lights are placed by `trafficLightPosition` (`src-tauri/tauri.conf.json`) at `x: 18`, the inset Finder's own lights have on macOS 26, and `y: 28.5`, which centres them on that row: `tao` grows the title bar to the button's height plus `y`, and the button's centre lands 2.5 pt above `y` (measured on macOS 26.6, `y: 16` drew it at 13.5 pt). A row height that changes moves `y` by the same half.
- The lights sit in the bar's first 84 px: their last button ends at 72 px, so the bar's first control starts at 84 px under `html[data-chrome='overlay']` and at 12 px without it (`src/presentation/navigation/path-bar.module.css`). In fullscreen the lights are gone, so `wearDress` (`src/presentation/navigation/chrome.ts`) drops `data-chrome` while the window fills the screen, and the bar draws its plain 12 px, as off a Mac.
- The material is one `underWindowBackground` effect under the whole window, its state following the window's (`windowEffects`), on a window made `transparent` and dark (`theme`, so the effect is the dark material whatever the system's appearance). Over it the canvas is drawn at `--material-canvas` (86 %) and the sidebar at `--material-sidebar` (72 %), through `--ground` and `--ground-sidebar`; panels, wells and every colour token stay opaque, so text keeps its contrast.
- `data-material="vibrant"` is set by `wearDress` in the Tauri window on a Mac alone (the user agent says `Macintosh`), so the translucent tokens apply nowhere else, and no golden moves.
- Transparency uses macOS's private API, which `tauri` enables unconditionally since 2.12.1 (`macOSPrivateApi` is a no-op there), hence `tauri = "2.12.1"` in `Cargo.toml`: the window is not for the App Store. No capability and no CSP changed.

## The window shows itself at its first data

The window opens hidden (`"visible": false`, `src-tauri/tauri.conf.json`) and shows once, when its first frame holds data, so no empty glass and no "Engine connecting" frame is ever seen at launch; a slow engine shows it at 800 ms with whatever is drawn.

- The rule is `Launch` (`src/application/use-cases/launch.ts`), over the port `LaunchPort`: it shows once both the frame holds data and the document's faces are loaded, or at `LAUNCH_CAP`, 800 ms counted from the page's load (`performance.now()`), whichever comes first, and never twice.
- The frame holds data (`holdsData`) at the commit where `machines.list` has its first out, partial or whole, or its refusal, or where no engine answers the socket, the core's panel being then the page, or where the engine is judged incompatible, the verdict's panel being the page. `Launched` (`src/presentation/navigation/launched.tsx`), drawn beside the `Window` in `main.tsx`, watches the frame's own `machines.list`, so the engine is asked nothing more, and tells the launch from the effect of that commit.
- The faces never swap on screen. Every face is `font-display: block` (`FACES_BLOCK`, `src/presentation/ui/faces-block.ts`, the PostCSS pass `vite.config.ts` runs, rewrites `@fontsource`'s `swap`), and the launch loads the five weights `document.css` imports (`FACES`, `src/infrastructure/outbound/launch-document/document-launch.ts`) as its script starts, before the window shows.
- Only the Latin faces ship. `FACES_SHIPPED` (`src/presentation/ui/faces-shipped.ts`, the PostCSS pass beside the other) keeps of each `@fontsource` face the `latin` and `latin-ext` subsets and Geist Mono's `symbols2`, in `woff2` alone: twelve files, of the forty-one the five imports declare. Text in Cyrillic or Vietnamese is drawn by the system's face, and `src/presentation/ui/__tests__/faces-shipped.test.ts` fails when the source draws a character only a dropped subset holds, or one no face of the kit holds that is not named there as the system's (⌘ ⌃ → among them).
- The show is the shell's command `window_ready` (`src-tauri/src/window.rs`), reached through `tauriShow` (`src/infrastructure/outbound/launch-tauri/`); a proof build has no window to show, and its `NO_SHOW` asks nothing. Like the other commands it needs no capability.
- The shell holds its own cap, `HARD_CAP` (1.5 s from its setup): past it the shell shows the window whatever the page did, so a page that never ran, threw first or was refused its show still shows. On a Mac, a click on the Dock while no window is on screen shows the window, unminimized and focused (`RunEvent::Reopen`).
- The Linux bench proves the rule by its specs and the shell by its tests; that the first frame a Mac shows holds the page is the owner's eye at the next release, since the vibrancy window is drawn on a Mac alone.
