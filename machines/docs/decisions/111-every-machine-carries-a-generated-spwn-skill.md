# ADR-111: Every machine carries a generated `spwn` skill

**Status:** Proposed
**Date:** 2026-11-28

## Context

An AI agent that runs on a machine of the estate starts blind: it does not know which machine it is on, whether `rg`, `gh` or `agent-browser` is installed, or that `station` can tell it. The owner asked for "un systeme de skill d'injection du systeme spwn": one skill that tells the agents every tool they may use, and explains spwn whole.

The static `studio-toolbelt` skill already projects the catalog. But it says every package of the catalog, not what this machine carries, and nothing of the machine itself or of the commands that drive it. A hand-written page of commands would go stale the day a command moves.

## Decision

Every machine gets one skill named `spwn`, written by the engine at the end of each apply run to its end (a create's boot phase included, never an image's bake) and of each update, the night's included. It lands in `~/.agents/skills/spwn/SKILL.md` and `~/.claude/skills/spwn/SKILL.md`, owned whole by Machines and listed in its footprint. Its three sections each have one owner:

- **Where you are**: the machine's resolution (name, kind, system, `vm.mounts`, `ports.*`). The Mac a VM runs on was asked for too, but a VM's own profile does not name its Mac, so the skill leaves it out until it does.
- **The apps present**: the apps that read present, each with a new optional package key, `agent:`. That key is one line of at most 160 bytes, decoded strictly, saying when to use the app and its one command shape. A package without it is said by its description.
- **How to drive spwn**: generated by `make generate` from the command tree and the two READMEs into `apps/engine/catalog/spwn/drive.txt`, embedded in the binary. A test fails while the file differs from the tree.

The file holds at most 8 KiB. Past that it names the tools with no agent line, then every tool, by name only, and points at `station apps <name>`, whose detail now shows the agent line. It is deterministic and written only when its bytes change.

## Alternatives

- **The drive section from `cmd/generate`.** The command tree is built only by `wire.Build`, which `cmd/generate`'s import row does not allow, and an allowlist of `specs/architecture/` only shrinks. A test of `specs/architecture`, which builds the tree already, writes the file under `-update-drive` instead, and `make generate` runs it.
- **Every command with its short line and its examples.** The tree's short lines alone are some 9.5 KB, so that does not fit the bound. Each noun keeps its short line, and each command its use.
- **A hook in Claude Code's settings that prints the machine at session start.** That works for one agent only, where a skill folder is read by every agent the `skill` method serves.

## Consequences

- An agent on any machine reads where it is and what it may run, in its own skill list, with no command to know first.
- An app's `agent:` line is catalog data: it changes by a package file, and a wrong line is fixed there for every machine at its next apply.
- A machine that never applies a Machinefile carries no skill, and an interrupted run leaves the last one as it was.
- **Open question:** does the `spwn` skill retire the static `studio-toolbelt` projection? Both now tell an agent what tools exist. The toolbelt says the whole catalog with its replacements, and the `spwn` skill says one machine. This record does not remove the toolbelt; the owner decides.
