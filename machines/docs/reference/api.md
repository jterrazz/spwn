# The API

`station.api/v2` is how every caller reaches a call on another process or another machine: the CLI reaches this Mac's engine with it, the menu bar does, a Mac reaches another Mac's engine with it over ssh, and an engine reaches the guest inside each VM with it ([ADR-016](../decisions/016-api-v2-and-remote-by-api.md)). Where a call runs is [Architecture](../concepts/architecture.md#the-router)'s.

| Section                   | Answers                                                               |
| ------------------------- | --------------------------------------------------------------------- |
| The transport             | The sockets and the ssh bridge the frames travel on                   |
| The frames                | One JSON object per line, and what each key means                     |
| calls.json                | The list of calls, generated from the Registry and the engine's own   |
| packages/api              | Every call's schema and the TypeScript types, generated               |
| The engine's own calls    | What a process of this Mac asks of the engine's live state            |
| The compatibility verdict | Whether a client draws this engine's pages, and the words that say it |
| Errors                    | The error object and its codes                                        |

## The transport

| From                  | To                   | How                                                                                                                                                         |
| --------------------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| a process of this Mac | this Mac's engine    | the unix socket `~/.local/state/station/engine.sock`, mode 0600 (`remote/adapter/unix`)                                                                     |
| this Mac              | another Mac's engine | `ssh -o BatchMode=yes -- <mac> station engine attach`, which bridges ssh's stdio to that Mac's socket (`remote/adapter/sshstdio`)                           |
| a Mac's engine        | a VM's guest         | `station guest serve --stdio`, run over the engine's one guest connection to the VM                                                                         |
| a process in a VM     | its Mac's engine     | the guest's socket `~/.local/state/station/guest.sock` inside the VM, relayed to its Mac's engine over that same connection; the VM holds no key to its Mac |

The engine listens on no TCP port, and the reserved ports' forwarders bind `127.0.0.1` only (the rule `engine-no-tcp`).

## The frames

A frame (`remote/api.Frame`) carries `v` (2) and `id`. A request carries `hello`, `call` or `watch`, with its `target` (`{name, on}`: the machine, and the Mac a VM runs on), its `in`, and `by`, the session it is done for, absent for you; its answers carry the same `id`: `progress` frames (`{task, detail, done, error}`, and on a guided call `act` and `step`, the act it belongs to and the step of its rail it reached, and on the one frame that first names the act its `guide`, the act's Guide as `engine.guides` serves it, which no later frame repeats), then one `out` or one `error` for a call, `out` frames then `done` for a watch. A `cancel` frame (`{v, id, cancel: true}`) names a request still answering on that connection and ends it there: a caller that lets go of a watch sends one, so the far side's producer stops. On the engine's socket a watch holds its connection, so closing it ends the watch. A frame whose `target` is another machine, a call or a watch alike, runs there: its name resolved as a call's (`mac-mini` for `mac-mini`), its answers relayed as they come, its end there ending it here, and a machine that does not answer refused as `remote.unreachable` before any `out`. The first frame of a connection is `hello`: the far binary's version and the calls it serves, so a call it does not serve is `far-too-old` before it is sent; with them, the `kind` of the machine that answers (`computer`, `workspace` or `server`). Its `abilities` name what those calls honour of an input that an older binary would decode as absent (`ports.share.to`, the audience of `ports share --to`; `machinefile.apply.leave-asking` and `machinefile.apply.within`, what a create's apply leaves and its bound): a request whose input asks one the far hello does not list is `far-too-old` before it is sent, a VM's guest's included, so it never runs without it. The hello a caller sends names its own `version`. Until 1.0 either side serves only its own release, whatever the other serves ([ADR-072](../decisions/072-before-1-0-every-station-runs-the-same-release.md), `machines.SkewOf`): a release is `vX.Y.Z` or `vX.Y.Z-<pre-release>`, and a `git describe` past one (`<tag>-<n>-g<sha>`, `-dirty`) is judged as that release. A far station on an older release, or on the numbering before the line restarted at v0.1.0 (a v3 station), is `far-too-old`; one on a newer release is `remote.caller-too-old` here, before any call is sent; the far side refuses a caller on another release as `remote.caller-too-old`, its hello still answered. A peer that names no release (`dev`, `dry-run-<sha>`, a bare sha, none) is a build of no release and passes; a station that is itself such a build serves only such builds. A VM's guest server reads its stdin to the end before it answers, so its hello is asked alone before each call. The calls of one connection are answered in the order they came. A far side that takes the connection and does not answer its `hello` within 5 s (`api.HelloBudget`) is a machine that does not answer, its connection ended ([ADR-074](../decisions/074-a-far-station-answers-its-hello-within-5-seconds.md)). A `by` that is no session's name (lowercase letters, digits and `-`, 1 to 40 characters, never `you`) is refused as `call.bad-input` before the call runs: an engine job's own name never rides a frame. An input that sizes what a call makes past the most it takes is refused as `call.too-large` before the call makes anything, naming that input and its maximum: `activity.read`'s `graph` takes 30 days at most (`calls.MaxGraph`).

A request's `far` is `true` when it came from another machine. The server that serves another machine's frames (`engine attach`, at the end of ssh) marks every frame it reads far, and the mark rides every hop after it: a frame may set it, never clear it. A call that is the owner's at the Mac alone refuses a far request, as `devices.add` does ([ADR-092](../decisions/092-a-machines-device-book-says-who-may-reach-it.md)).

```text
→ {"v":2,"id":"7","call":"machines.create-workspace","in":{"Request":{"Image":"linux","Lifetime":"ephemeral"}}}
← {"v":2,"id":"7","progress":{"task":"Booting linux-1"}}
← {"v":2,"id":"7","out":{"VM":{"Name":"linux-1"}}}
→ {"v":2,"id":"8","call":"engine.stop","in":{"Confirm":"inf"}}
← {"v":2,"id":"8","error":{"type":"needs-confirmation","code":"confirm.yes-needed","subject":"stop","message":"refusing without --yes: stop","hint":"re-run with --yes"}}
```

## calls.json

[`apps/engine/remote/api/calls.json`](../../apps/engine/remote/api/calls.json) is the Registry and the engine's own calls, projected by `make generate` (`station.calls/v1`): each call's `name`, the `schema` of its output (`station.<call>/v<n>`, the version of the document `--json` prints, the call's `Document`: `station.machinefile.plan/v3`), its `section`, its `where` (`at-target`, `in-engine`, `in-process`), the confirmation it may require, with its `consequence`, the sentence the engine words for what that action ends (`%s` is the subject the question names), `confirm_by`, the confirmation a kind of target asks instead of it (`machines.restart`: a server's `restart-server`, a workspace's `restart`), `guide`, the family of the act the engine guides it as when it is one (`machines.create` for `machines.create-workspace`; its Guide is `engine.guides`'s, [machines](machines.md#macs-and-vms)), the `errors` it declares, its input and output types, `watch` for a read that fills progressively, `journal` for a gesture that keeps a line in its Mac's journal ([The journal](journal.md)), and `own` for a call the engine serves beside the Registry (below). The engine serves every call of it, a Registry's call run on this Mac as the CLI runs it; the menu bar names its actions by these names; `api_test.go` fails when the file differs from the Registry and `enginecalls.Owns`.

## packages/api

[`packages/api/`](../../packages/api/README.md) is the same wire, machine-readable, written by `make generate` from the Go types: `schemas/calls/<call>.json`, one JSON Schema per call of `calls.json` (its `in`, and the `out` of each answer), `schemas/frame.json` (the frames), `schemas/event.json` (the events of a watch of pages), and `index.d.ts`, their TypeScript, with `Calls`, the map a client types `call('ports.list', input)` by, and `StationWords`, the type of `words.json`, which `words.d.ts` declares for an import of it: the word, detail, heading, nouns and tone of each value of the closed enums a client draws (a condition, an action and the heading of the lines it names, a level, an audience, a state, the nouns a client counts after a number (a machine, a skill, a listener, a short-lived listener left out of Ports), a refusal's type and its code, called by its name read as words with its family as detail, the `code` of an error a closed enum of every code `surface/cli/words` words, the engine's own `unknown_vm` and its kin included, a section), a `Record` per enum so a value without its word fails the client's compiler. Its drift test fails `make test` when a file and the Go types differ, the recorded streams and page fixtures are checked against its schemas, and `answers-match-schemas` sends every read that asks no confirmation to `guest serve --stdio` of the spec build over each world and checks each answer against its call's schema; `activity-answers-match-schemas` checks the same of the window's `activity.read` recordings, graphs and histories in them, and of an `engine.activity` answer of a series the engine kept.

`install.json` (typed by `install.d.ts`, exported as `./install.json`) and `schemas/station.engine-record.v1.json` and `schemas/station.install-record.v1.json` tell a client what no call can while the engine does not answer: where Machines is installed (`catalog.InstallDir`, the binary's name, the install line), where the engine records the binary it last started from, `{state}/station/engine.json` (`engine.Record`: `v`, `executable`, `version`, `at`), written whole at each engine start, and where the public installer records the binary it installed, `{state}/station/installed.json` (the same shape, `station.install-record/v1`), written atomically by the installer at the end of a successful install that installed a station binary (a platform with no station build gets spwn alone, exits 0 and writes none; an older record is left byte for byte and never deleted; an install path with a control character, below 0x20 or 0x7f, is refused before any write); the engine owns that contract and never reads the file. The state root is `$XDG_STATE_HOME` when it is an absolute path, else `$HOME/.local/state`: installer, engine and window agree on it. A client looks in this order: the running engine's `engine.hello` `executable`, the engine record's, the install record's, then the install folder. The record is always the same file: a later shape bumps its `v` and replaces the file whole, and a reader that does not know a record's `v` ignores the record and falls back to the install folder; `install.json` changes shape only by a new `station.api` version.

Every verdict an answer carries is one shape, the word and tone of the verdict and an optional `Line`, the sentence under it: the head of a Mac's Overview (`Summary.Head.Verdict`: online with the machines it runs, its line how long it is up, or its engine stopped; absent on a VM, whose head is its `Head` in `machines.list`, said by its Mac from the drift its engine keeps, `Pending` until the first reading or while its Mac's engine cannot read it), the head of Home and what a machine page draws under its own (`Summary.Verdict`, which names a server down, else counts what needs you, its line the rest and the machines of its Mac counted, by its name (`4 machines on macbook-pro`; asked with `Elsewhere`, which only the window's Home and Inbox send, the engine reads the other Macs too and the head says their roll-up, `Elsewhere, 1 machine down.`, and claims nothing of them until that read ends), and `Summary.Read`, when the reading was made), a machine's `Health`, a Mac's Awake (`awake.read`'s `Verdict`, absent while its engine reads, each case in [Awake](awake.md#the-verdict)), Ports' `verdict`, the accounts and the vault's (its `Line` says a value never leaves this Mac's Keychain to be shown), the catalog shelves' (`Verdict` and `Skills` of `apps.matrix`, `Verdict` of `settings.matrix`: each a `Mine` and a `Catalog` verdict) and the Machinefiles' (`machinefile.files`, over its files). A need says its `Upkeep` (`needs-you` for whatever is broken, in any section, a sign-in expired or a background task failing as much as a machine down; `can-wait` for the rest), its `Verb` (a closed set, worded by `words.json`), its `Mark` (`exposed` for a port reachable outside with no declaration, `down` for a server that is down, `not-created` for a VM whose create failed, else its `Upkeep`, each worded by `words.json`, whose `can-wait` reads "Upkeep"), its `Detail` (the sentence under its title when its finding tells one: an exposed port's machine and process, a server's Mac, since when its check fails and whether SSH still answers) and its `Noun`, the tab its line names after its machine (`Sign-ins` for a sign-in), so a client words no urgency of its own. An exposed port is reviewed on its machine's Ports and carries no `Command` or `Path`: the System Settings path stays on its port's row. A need fixed by a call names it in `Call` and its input in `Args`, each key a field of that input as its schema in `packages/api` names it (a list field holds the one value given, `{"Managers": "brew"}`); `On` is the machine the call runs at (a VM's restart or delete goes to its Mac), and `Confirm` the name its question takes typed, when it asks one for that machine. A finding of `activity.read` also carries `Again` (always present): true when its fix runs again what failed to begin, as the start of a VM whose create failed does, so a client, a far Mac's included, words that button `Try again`, not its call's; the need made of it says it as its `Verb` `try-again`. A Mac's `Summary.Machines` is the sentence of its machines (`3 running, 1 stopped`); Ports' `verdict` is of the machine `ports.list` was asked for, the short-lived listeners it leaves out counted in its `Line`; a Mac's `Answered` in `machines.list` is absent for a Mac never heard, and its `Sentence` tells it in one line: its engine and how it sleeps (`Engine running. Awake until 18:00, lid closed.`, `Engine running. Sleeps normally.`), or since when it is not seen (`Not seen for 12 min. Asleep or off the network.`), its `Awake` the words of how it sleeps (each variant in [machines](machines.md)).

The release reading is two calls of the Registry, so a window finds it in a hello's `calls`: `engine.read-release` answers what the engine kept of GitHub's latest release, with no network, and `engine.refresh-release` asks GitHub again first; both answer `Installed`, `Latest`, `Behind`, `Head` (a verdict), `Notes`, `Checked` and `Refused` ([Machines](machines.md#the-engine)).

The journal is two calls of the Registry: `journal.kept`, at the target, answers one Mac's `Lines`, newest first, from `Since` to `Before`, and `Mac`, the name its engine goes by, so the asker reads that Mac's own lines under the name it added it by; `journal.read`, in this process, asks each Mac and answers `Groups` (each `Day`, `Title`, `Sum`, `Night` and its `Lines`), `Unheard`, `Next` and `Empty`, narrowed by `Mac`, `Machine` or `Subject`, paged by `Before` and `Days`, or `Night` alone. A line's `At` is an RFC 3339 instant, and its `Outcome` and a subject's `Kind` are closed enums with their words ([Journal](journal.md)).

The device book is three calls of the Registry, each applied on a Mac alone. `devices.list`, at the target, answers `Mac`, `Key` (this Mac's own device key line, empty where it has none), `Devices`, the entries whose seal holds, and `Broken`, the ones whose seal does not, each `{name, key, fingerprint, channels, added}` and never its seal. `devices.add`, in the engine, takes `Name`, `Key` (the `.pub` line) and `Channels` (none is all three) and answers the new entry; it refuses a far request, then asks the owner's presence (`devices.presence-refused`, `devices.no-presence`). `devices.forget`, in the engine, takes `Name` and `Confirm` (the `forget-device` confirmation, the device's name typed) and answers `{name}`; it asks no presence and serves a far request.

The approvals are one call of the Registry, applied on a Mac alone ([ADR-105](../decisions/105-macos-approvals-have-one-owner-the-engines-approvals-table.md)). `approvals.list`, in the engine, answers `mac` and `rows`, one per approval in the table's order, each `{id, state, holder, required, sentence, fix}`: `id` is a closed enum (`local-network`), `state` is `approved`, `refused`, `checking` (a refusal in the engine's first 90 s) or `unknown` (a read that cannot tell), `holder` the app macOS charges with it (`Spwn` when the app carries the engine, else `station`), and `fix` the fix of every document (`call`, `command` and `path`, null when unset, `pane` only while one is owed), set only by a refused row: the Local Network pane with its path. It is the view of the same name, so it never reads macOS itself; with the engine down it answers the engine's down error.

`engine.log`, at-target and applied on a Mac, answers what Machines wrote on it: the last 500 lines of the engine's log (`~/.local/state/station/logs/engine.log`, read from its last 256 KiB, so a log of any size answers in one read), each line with its secrets withheld ([ADR-048](../decisions/048-the-engine-withholds-a-secret-before-any-answer.md)), and `Empty`, the engine's sentence, when there is none. It is the window's reading of what Machines did on a Mac; `machines.log` stays a VM's.

`engine.state`, a watch of the Registry served by a Mac's engine, streams the engine's read model ([ADR-070](../decisions/070-the-engine-keeps-one-read-model.md)): the slices its readers keep warm whether or not a client watches, each by its key, `<family>:<machine>` (`mac:`, `ports:`, `overview:`, `awake:`, `activity:`, `signins:`). Its input names `keys` (an exact key, `<family>:*`, or `local`, every key this Mac reads itself; none is `engine.state-no-key`, a key of no family `engine.state-unknown-key`, both on the field `keys`, and both judged only for a client at the engine's own revision: one of another revision is answered its verdict whatever keys it names), `revision`, the revision of `station.state/v1` the client reads, `hold`, `since` (`epoch`, `rev`) and `pace`, `idle` for a held stream that leaves the engine's readers at their idle pace, as another Mac's engine asks while no client is attached to it (any other pace holds them at the attached one). Every other Mac's `local` stream is held by the engine ([ADR-072](../decisions/072-before-1-0-every-station-runs-the-same-release.md)), so that Mac's slices are in this one's store under that Mac's keys (`mac:mac-mini`, `overview:infra`), named by an exact key or `<family>:*`, never by `local`: a Mac whose stream stops, or sends no frame for 45 s, keeps its last values, `stale` with the `why` `unreachable`, and is dialed again after 5 s, 10 s and 30 s, then every minute; one whose engine serves no `engine.state` is `far-too-old`, never read by the older calls. Each `out` is a frame of one `event`: `opened` (`stream`, `state` and `page`, the revisions the engine speaks, `epoch`, and `fit`, the verdict on `revision`, after which a misfit ends), then `snapshot` (`rev`, `at`, and `slices`, each asked key's `value`, `hash`, `read_at`, `state`, `fresh`, `stale` or `unread`, and `why`), answered at once from the store, never from a read; or, given a `since` of the same engine still in its last 256 revisions, `changed`, only the keys whose hash or state moved, with `gone`. Unheld, the watch ends there; held, a `changed` follows each revision, gathered over 250 ms, and a `tick` every 15 s, the stream's liveness. A slice holds facts, never a value of the clock: an Overview's reading instant is its `read_at` and its uptime the machine's `Boot`, so an unchanged machine keeps its hash. Beside the slices, `keys` names the window's views, each a projection of the store named as the call whose answer it is: `machines.list`, `overview.read` (This Mac's), `overview.read+elsewhere` (This Mac's, the other Macs' roll-up in its verdict), `overview.read:<machine>`, `ports.list+all-machines` (every Mac's ports, This Mac's node on the tailnet with them) and `ports.list:<machine>` (one machine's, as `Of` names it), `accounts.list` (This Mac's sign-ins) and `accounts.list:<machine>` (a VM's or another Mac's), `awake.read` (This Mac's) and `awake.read:<mac>`, and `engine.guides`, the Guides of the long acts its engine guides, drawn from its `acts:` slice and fresh and empty before the first, and `approvals.list`, This Mac's approvals, drawn from its `mac:` slice; a view of every machine is asked as `<call>:*`. A view's value is its call's answer but for when it was read: its words are said as of the store's instant, and the instants it carries are those its facts were read at, an Overview's uptime with them, so a revision that only moves the clock sends no view. Each revision's views are projected once, for every stream that holds them. A view is sent whole in a snapshot and on a resume, and in a `changed` only when its bytes or its state move; its `state`, `why` and `read_at` are those of the slice it is drawn from, This Mac's `mac:` for the machines list and its `ports:` for the ports; an Awake's `Now` is its slice's `read_at`, its choices and verdict said then. A door that is not the engine (`guest serve --stdio`) relays the engine's stream.

## The compatibility verdict

A client judges an engine before it draws any of its pages. A watch of pages declares the `revision` its client draws, and its opening carries the engine's verdict on it, `fit`: `verdict` (`fits`, `engine-older`, `app-older`), `engine` and `app`, the two revisions (`engine.FitOf`). A watch that does not fit ends at its opening, so no page reaches a client that cannot draw it, and a client that declares no revision is older than the verdict. A client that watches no page judges `engine.hello`'s `page` by the same rule. Until 1.0 there is no range: a client draws one revision, a single constant (the menu bar's `pageRevision`, held equal to the engine's `page.Revision` in one tree by `apps/engine/page/revision_test.go`, and the window's `STATE_REVISION`, declared on its `engine.state` stream), and only an engine at that revision fits ([ADR-072](../decisions/072-before-1-0-every-station-runs-the-same-release.md)). The verdict is ADR-070's one rule, worded the same in the menu bar and the window:

| The engine's revision       | The verdict                      | The remedy, and its command                                                       |
| --------------------------- | -------------------------------- | --------------------------------------------------------------------------------- |
| the client's revision       | compatible: its pages are drawn  |                                                                                   |
| below the client's, or none | `engine older than this app`     | `Update station here`, with `catalog.InstallLine`, the line that installs station |
| above the client's          | `this app older than the engine` | the client's own update (the menu bar: Spwn.app's, `open -b com.jterrazz.spwn`)   |

An incompatible engine is running, so it is never said stopped: the menu bar's item reads `Spwn Menu: engine older than this app`, dimmed as a stopped one is, and its panel draws the engine's own page of the verdict, `menubar.home.engine-outdated`, with none of the engine's pages ([`Subscription`](../../apps/menubar/sources/station-kit/engine/Client.swift) drops them).

A revision of `station.state/v1` names what a window and an engine must both understand to talk at all: the views the window asks in its one `engine.state` request, the forms its confirmations are asked and answered in, and every field and member of the wire a peer reads as always there. Both sides hold it as one constant, the engine's `engine.StateRevision` and the window's `STATE_REVISION`, held equal in one tree by `fit.test.ts`. It is raised when any of those changes, so a window and an engine of two trees that no longer understand each other say so by the verdict rather than break. Revision 2 exists for three changes revision 1 does not carry: the view `engine.guides`, which an engine of revision 1 refuses as `engine.state-unknown-key` with every other view of the request; a yes-or-no question the engine raised answered with the name it asked about, where revision 1 takes only `yes`, and the forms confirmation by consequence gives each gesture ([ADR-097](../decisions/097-a-confirmation-follows-its-consequence.md)); and a need's `Pane` and `InTerminal` and its verbs `open-settings` and `in-terminal`, which revision 1 does not send.

### What raises the revision

A change raises the revision when a peer of the revision before it cannot ignore it; one it can ignore is additive and raises nothing ([ADR-101](../decisions/101-a-change-an-older-peer-cannot-ignore-raises-the-state-revision.md)). `packages/api/revision.json`, written by `make generate`, pins each such thing as it was first generated at the revision, and `TestAChangeAnOlderPeerCannotIgnoreRaisesTheStateRevision` (`apps/engine/cmd/generate/revision_test.go`) fails, naming each pin that moved, until the revision is raised on both sides and the file generated again.

A revision no release carries yet takes a breaking change in: its record is deleted and `make generate` writes it anew at the same number. A revision a release carries is never rebuilt: the number rises. The newest release tag says which: its `packages/api/revision.json` holds a lower `state`, or the tag has no record at all (`git show "$(git describe --tags --abbrev=0)":machines/packages/api/revision.json`).

| Breaking: raises the revision                                                      | Additive: raises nothing                                    |
| ---------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| a view the window adds to, or drops from, its `engine.state` request (`VIEW_KEYS`) | a view the engine adds, which no window asks yet            |
| a confirmed call's form, or the form a kind of target asks, in `confirms.json`     | a confirmation's consequence, its words                     |
| a field of an answer added or kept without `omitempty`, so a client reads it there | a field added under `omitempty`, so a client reads it maybe |
| a required field retyped, renamed, removed or made optional                        | a field of an input, which a server reads absent as zero    |
| a member added to or removed from an enum, on any field                            | a new call, or a new type behind a field left optional      |
| a call's `in` or `out` changed to another type                                     | a call removed, refused per call as `call.unknown`          |

What a peer does with an answer it receives is not pinned: a change of how the engine reads a confirmation's answer, as revision 2's yes answered by the name, raises the revision by the author's judgement, since no schema says it.

## Errors

An error carries its `type` (which decides the exit code), its `code` (a call's own, `call.unknown`, `call.bad-frame` for a line that is no v2 frame, `broke` for a call or a watch whose handler panicked, the engine and the connection kept, its `detail.log` the engine log that holds the trace, or the engine's: `unknown_vm`, `temporary`, `not_running`, `range_full`, `max_per_vm`, `ignored_port`, `not_allowed` (a guest's share outside its VM's rights), `guest_timeout`, `guest_output_too_large` (a command inside a VM that printed past the 8 MiB its stdout or its stderr is kept, `contract.GuestOutputMost`, ended there, the VM named), `local_network` (a VM's guest its Mac refused for Local Network the whole minute), `internal`, `awake_guard`, `awake_range`, `awake_unsupported`, `unknown_page`), its `subject` and `detail`, the `field` of the input a refusal is about when it names one (`label`, `value`, `term`, or `keys`, the keys of an `engine.state`), a `message` and a `hint`, worded as the CLI prints them. A watch takes its connection: a later line on it gets no answer, so a client sends its calls on a second connection. The first page is drawn at once from what the engine's store holds ([ADR-070](../decisions/070-the-engine-keeps-one-read-model.md)), never after a read, and the values the live ticks kept of its keys follow it as a `sample`; then a page whenever a revision of the store changes it, coalesced over 250 ms and never resent unchanged; a client that does not read for 5 s is dropped. The pages are `menubar` (Home), `menubar.machine:<name>` (one machine's page, `menubar.machine:infra`), `menubar.ports[:<machine>]` (every Mac's ports, one Mac's and its VMs', or one VM's: what is exposed first, then what is public, private and only listening, a port shared in the last 8 s marked `fresh`), `menubar.awake`, `menubar.activity[:<machine>][:6m|1h|24h]` (This Mac's activity over that window, 1 h unless named, or a named machine's: a Mac's read through its engine, a VM's through the engine of the Mac that runs it; each window's CPU comes folded as its chart draws it, 72 bars of 5 s, 60 of a minute or 48 of 30 min, each with its mean and its busiest share, and the window's peak), `menubar.accounts[:<machine>]` (every Mac's accounts, one Mac's, or the copies a VM's Mac shared with it), `menubar.needs[:<machine>]` (what needs you, then the upkeep, of every machine or of one), `menubar.find` (the Find index) and `power`. Each but Activity is a projection of the store, drawn once per revision for every watch of it; Activity is read only while a client watches it. A page lists in `live` the keys its moving numbers follow (`<measure>:<machine>`, the measures `cpu`, `memory`, `free`, `disk` and `net`: `cpu:linux-1`, a VM's share of its own cores read inside it; and `cpuh:<vm>`, a VM's CPU as a share of the whole Mac that runs it, read on that Mac from the Virtualization process that runs its guest; and `memh:<vm>`, the memory that process holds on that Mac now, as read and with no series), and each of its values that moves names its key in its own `live`. While a watch is open the engine reads every 2 s the keys of every open page, all watches' at once, and sends each watch one `event` `sample`: `at`, `values` (each of its pages' keys and its value as the page draws it, the measure now led into its series as a `spark` value, `free` alone) and `stale` (the keys whose machine has not answered for more than 30 s, kept at their last value and marked `stale`); so two pages that show one key show one value in one tick. Each machine is asked through its engine, a VM's and another Mac's as the machine page reads them, and a tick waits on a late one for 1 s at most. A page is never rebuilt on a tick, only when a slice it is drawn from changes: the engine's readers keep each slice at its own cadence, and `refresh` makes every reader due. Another Mac's parts of a page are the slices that Mac's engine streams to this one, so a Mac that does not answer holds back nothing: a machine's first page carries its header, kind and standing. A Mac's page carries its segments (Overview, Activity, Ports, Accounts) and every segment's sections at once, so the app picks a segment without a read, its Accounts pending until its sign-ins answer, so a page read but for them is not full; a running VM's page carries its own (a server's Overview and Activity, a workspace's four), and a stopped one none; a Mac's Ports ends on its HTTPS links switch (`ports.set-https` on that Mac). A server's page carries Overview and Activity the same way: its facts, the Mac it is on a part whose `nav` is that Mac's page, its Health (folded behind its count while healthy, open by itself while a restart walks its four steps with the one running counted, the down banner with Restart and why, or Stopped with Start), its check's latency over the last hour, its last 30 days, the last lines its console kept while it is down, its gauges (their last values while it cannot answer, waiting while it restarts), its ports (each row copying the address that reaches it: a port declared public the site its check asks when that site is served there, else its name and port), and its `footer` (its ssh and Open in Terminal, which waits with its reason while it cannot answer). A machine's Activity carries its three windows at once, read with the page from the history its engine keeps (the 6 min from its seconds, the hour from its minutes, the day from its 15 min, [Activity](activity.md#the-history)'s tiers): 72 points of 5 s, 60 of a minute and 48 of 30 min, each the mean of its span and when it starts in the words a scrub says it (`2 min 35 s ago`, `24 min ago`, `14:00`), with the window's peak and, when the CPU stayed at or above 90 % around it, that run and its sentence (`Peaked 94% at 03:10`, or `CPU on mac-mini has been above 90 % for 12 min` while it holds), the network sent over received, then the memory now and the busiest processes, a Mac's VMs among them; the window picked is the app's own, the hour until one is picked for that machine. A Mac's page reads that Mac's Awake and the copies every Mac shared for its Needs you, folded after three rows, and a Mac not heard from for more than 30 s has its gauges and rows drawn stale and no header marking, its VMs, Overview and Activity the last its engine sent. Ports, Awake and Accounts: each Mac's as its engine keeps it. Accounts lists what needs you, then every copy shared with a VM with its time left and its total (`left`), then every account signed in somewhere with the Macs that hold it, in the order [Accounts](accounts.md) gives. Awake has This Mac's card (its switch, the terms `1 hr`, `4 hr` and `Until 18:00`, none picked while it follows a run, which a line names, and the switches its capabilities allow), the running work that pauses while it sleeps, then one card per other Mac: its policy, what depends on it and its switch, a Mac asleep read as asleep with when it was last seen; it has no footer. Needs you: drawn from the machines, every Mac's ports and every answering Mac's Overview; it lists a server down and a port exposed first, then a copy ending in under 30 min, the soonest first, each a row with its verb, then the upkeep apart (a security setting, what fails, a sign-in, the updates as one row), which the badge never counts. Find: drawn from Home's own slices; one entry per row in its group (`needs-you`, `machines`, `ports`, `actions`, `sections`), each with its glyph, its title, where it is (`detail`), its tags (the `tags` cell), its verb (`verb`, whose action's `key` is the entry's), its alternate (`quick`) and the page it opens (`nav`), the needs in Find's words and ranked as Needs you ranks them; `verbs` holds each VM's verbs, a group headed by its name, for a query that begins it. Activity: every 2 s over its window. A machine is sampled every 60 s, and every 2 s only while a client holds `engine.watch` on it, as the menu bar does while its popover is open: a watch of pages or events alone never makes it so. Inside a VM, the guest's socket serves `engine.services`, `engine.reserve`, `engine.release` and `engine.agents-held` in the same frames, relayed to its Mac's engine.

An error's words and a progress `detail` leave with every secret in them withheld: each word `core/secret`'s `Screen` takes for a token, a credentialed URL or a key reads `withheld`, and every other word stays as given. `call.ToWire` screens the `message`, `hint`, `subject`, each `detail` value and the fix's `call`, `command` and `path`; the CLI's error block and `station.error/v1` screen the same fields; the serve loop and the CLI's spinner screen each `progress` detail. The frames keep their types, so `v` stays 2. `engine.guest-exec` is not an answer to screen: it returns a guest's raw output by design.
